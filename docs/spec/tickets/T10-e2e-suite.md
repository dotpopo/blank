| | |
|---|---|

| 预估会话数 | 2 |

## 目标

用 tester.army/e2e 把**关键流**钉住,让后续任何改动都能立刻知道有没有破坏核心行为。

## 环境约束(重要)

- e2e 要求 Node ≥ 22.22.3 / 24.8。本机 PATH 默认是 `22.22.2`,**不够**。
  跑之前把 `D:\nodejs`(24.16.0)放到 PATH 最前。
- 模型走 `LLM_BASE_URL` / `LLM_KEY` / `LLM_MODEL_ID` 三个**用户级**环境变量,
  已在 `e2e.config.ts` 里读 `process.env`,**不需要每次 export**。
- 需确认该网关支持 **tool calls + 图片**(e2e 的 agent 步骤依赖这两项)。若不支持,
  降级方案是只用 `expect` 写确定性断言,agent 步骤仅用于探索,不进 CI。

## 必须覆盖的用例

| # | 用例 | 断言方式 |
|---|---|---|
| 1 | 首页打开,水位数字可见 | 确定性 locator |
| 2 | 领取一个码 → 剪贴板有内容 + 水位减 1 | 确定性断言(水位数字前后对比) |
| 3 | 同一码领两次 → 第二次被拒 | 确定性断言 |
| 4 | 领满 3 次 → 按钮禁用 + 特定文案 | 确定性断言 |
| 5 | 贡献一个码 → 出现在最新列表 | agent.act + 确定性断言 |
| 6 | 贡献重复码 → 被拒且配额未扣 | 确定性断言 |
| 7 | 提交新应用 → 进入待审 | agent.act + 确定性断言 |
| 8 | 管理员登录 → 通过待审 → 应用出现在首页 | agent.act + 确定性断言 |
| 9 | 大盘数字随新增/领取变化 | 确定性断言 |
| 10 | 窄屏(390×844)下首页可用 | 独立 target + 确定性断言 |

## 交付物

- [x] `tests/` 下按用例拆分的 `.e2e.ts` 文件,命名与上表对应
- [x] 每个测试的**前置数据**是可重复构造的(用 SQL 或 RPC 造夹具,不依赖手工点出来的状态)
- [x] 测试之间**互不污染**: 配额是 localStorage 级的,注意用 `app.clearState()` 或独立 context
- [x] 一份 `docs/spec/testing.md`: 怎么跑、怎么加用例、失败怎么看、哪些用例依赖模型
- [x] 明确标注哪些用例**不需要模型**(应该占多数,因为更快更稳)

## 验收

- `npm run test:e2e` 全绿。
- 故意改坏一处(比如把水位数字写死),对应用例**确实变红**。
- 连续跑两次结果一致(不 flaky)。

## 不做什么

- 不追求覆盖率数字。
- 不测第三方(Supabase)本身。
- 不写视觉回归截图对比(超出范围)。
