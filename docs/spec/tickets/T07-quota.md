# T07 · 配额层

| | |
|---|---|
| 依赖 | T05, T06 |
| 阻塞 | T10 |
| 预估会话数 | 1 |

## 目标

实现 spec 第 7 节的本地配额。**它不是安防,是心理刹车。**
所以这一张工单的重点是**状态的可见性**,不是对抗绕过。

## 规则

- key: `opendoor:quota:<appId>:<YYYY-MM-DD>`
- value: `{ claim: number, contribute: number, dice: number }`
- 上限: 每项 **3**
- 重置: 换日期即重置(每天)
- 另存一个 `opendoor:browser_id`(随机 UUID),供 T01 的宽松兜底与大盘去重使用(spec 11.7)

## 交付物

- [x] `src/data/quota.ts`(不用 zustand): 读取、累加、查询剩余、跨标签页同步(`storage` 事件)
      > 偏离: 放在 `src/data/` 而不是 `src/store/`, 也没用 zustand。配额是浏览器本地的事,
      > 和适配器共用一份更省事, 一个普通模块就够, 不必引状态库
- [x] 日期边界处理: 跨零点时自动滚到新的 key(用户挂着页面到第二天,额度要能用)
- [x] **耗尽态 UI**: 明确文案 + 什么时候恢复
      > 偏离: **不禁用按钮**。禁用的按钮不告诉人为什么点不动, 点了给一句「今天的额度用完了,
      > 明天再来」比灰掉更有信息量。文案会变成警示色
- [x] 剩余额度**在按钮附近可见**(不是藏在设置里),让用户在点之前就知道还剩几次
- [x] localStorage 不可用时(隐私模式)的降级: 允许操作,但不计数,并**如实告知**
      (不要假装在计数)
- [ ] 手动重置入口仅对开发者可见,不进正式 UI
      > **偏离。重置入口在页脚, 所有人都能看到。判断是: 这个站的配额本来就只是心理刹车, 藏起来反而更可疑**

## 验收

- 领 3 次后,第 4 次的按钮禁用,文案是「今天的领取额度用完了,明天再来」这类**具体**的话。
- 贡献与骰子各自独立计数,互不影响。
- 改系统日期到明天,额度恢复。
- 两个标签页同时打开,一边领了,另一边刷新剩余额度。
- 清空 localStorage 后额度恢复(这是预期行为,不是 bug,写进注释)。

## 不做什么

- 不做服务端配额校验(spec 明确不要 IP)。
- 不做指纹识别、不做反作弊。
- 不做「用完了可以通过某操作获得更多」这类机制。
