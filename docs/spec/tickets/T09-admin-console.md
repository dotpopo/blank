# T09 · 管理后台

| | |
|---|---|
| 依赖 | T02, T03 |
| 阻塞 | T10 |
| 预估会话数 | 1 到 2 |

## 目标

管理员的工作台。设计原则: **队列优先**。
管理员每次进来大概率只做一件事: 处理待审应用。所以待审队列必须在第一屏,且能连续处理。

## 交付物

- [ ] `/admin` 登录页: 用户名 + 密码 → `admin_login` → token 存 `sessionStorage`
- [ ] **待审队列**: 一行一个申请,显示应用名、分类、描述、官网、提交时间
  - 通过时**必须设置该应用的有效期天数**(这是 spec 里明确要求的字段)
  - 驳回时填理由(理由要能回传给提交者看到)
  - 支持键盘连续操作(通过/驳回/下一条),不要每次都要用鼠标点
- [ ] **应用管理**: 列表 + 改有效期 + 下架
- [ ] **码管理**: 按应用筛选,支持**硬删除**(spec Q1 的 (b) 读法)
- [ ] **过期码清理**: 列出已过期未清理的码,支持批量硬删
- [ ] 操作日志: 谁在什么时候做了什么(从 `pool_events` 与审计字段读)
- [ ] token 过期时的处理: 明确提示重新登录,不要静默失败

## 验收

- 通过一个待审应用后,该应用下的待入池码**立即生效**,并在首页可见。
- 硬删除一个码后,池子总数减少,首页列表里消失。
- token 过期后任意管理操作给出「登录已过期,请重新登录」。
- 用错误密码登录,不泄露「用户名是否存在」。

## 不做什么

- 不做多管理员、不做角色权限细分(固定单账号)。
- 不做管理员修改自己的密码(直接改数据库)。
- 不做数据导出。
