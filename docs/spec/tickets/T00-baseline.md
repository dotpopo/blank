## 目标

让后续每一张工单都能在一个**可构建、可测试、约定明确**的地基上开工。

## 交付物

- [x] 分支 `feat/invite-pool` 存在,`main` 保持干净。
- [x] 依赖安装完成,`npm run dev` 能起服务(此时页面仍是空的,正常)。
- [x] `AGENTS.md` 写在仓库根: 记录本项目的**常驻约定**(技术栈、RPC 优先、无 em-dash、
      不用假数据、测试怎么跑、环境变量从哪来)。这份文件是新会话开局的 standing brief。
- [x] **设计读法**一行 + 三个旋钮的取值写进 `AGENTS.md`(见下)。
- [x] `.env.example` 补齐本项目需要的变量(不含真实密钥)。
- [x] 确认 `LLM_BASE_URL` / `LLM_KEY` / `LLM_MODEL_ID` 三个**用户级**环境变量在新 shell 里可见。

## 设计读法(必须在写第一行 CSS 之前定下)

一句话说明: 这是什么页面类型、给谁看、什么调性、走哪套设计体系。
三个旋钮必须**显式设定**,不能默认套基线:

| 旋钮 | 基线 | 本项目建议 | 理由 |
|---|---|---|---|
| `DESIGN_VARIANCE` | 8 | 待定 | 单页工具型产品,信息密度是主诉求,方差不宜过高 |
| `MOTION_INTENSITY` | 6 | 待定 | 动效只服务于「领取成功」这一个时刻 |
| `VISUAL_DENSITY` | 4 | 待定 | 水位计式的界面,数字要能一眼读到 |

## 验收

- `npm run dev` 起得来,`http://127.0.0.1:5173` 有响应。
- `npm run build` 通过。
- `npx e2e list` 能列出 target(证明 e2e 配置可加载)。
- `git status` 干净。

## 不做什么

- 不写任何页面组件(那是 T04 以后的事)。
- 不动 `main` 分支。
- 不提交 `.env`。

## 备注

- e2e 要求 Node ≥ 22.22.3 / 24.8。本机 PATH 默认解析到 `22.22.2`,**不够**。
  跑 e2e 前把 `D:\nodejs`(Node 24.16.0)放到 PATH 最前。
- e2e 官方说 Windows 上建议在 WSL 里跑。实测原生 Git Bash 下 `npx e2e init` 正常,
  但首次 `npx e2e run` 需要下载 Chromium,可能较慢。
