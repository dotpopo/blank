# T06 · 贡献流程与新增应用待审

| | |
|---|---|
| 依赖 | T03, T04 |
| 阻塞 | T07, T10 |
| 预估会话数 | 1 到 2 |

## 目标

把供给端做顺。**已上架的应用,贡献码免审,立即入池。**
**库里没有的应用,提交待审。** 这是 spec D5 的落点。

## 交付物

- [ ] 贡献表单(模态或独立页),字段:
  - **应用**: 搜索选择。搜不到时提供「申请新增这个应用」
  - **邀请码或链接**: 必填,按应用的类型给格式提示(见下)
  - **备注**(可选): 使用条件、地区限制等
  - **有效期**: 默认 = 该应用的 `validity_days`,**可覆盖**为具体日期
- [ ] 提交前**先按 slug 归一化匹配**已有应用(spec 11.8):
      命中已上架应用 → 直接挂码;命中待审应用 → 挂到待审应用上;都没命中 → 走新增申请
- [ ] 新增应用申请表单: 应用名、分类、图标(emoji 选择器,不用假截图)、一句话描述、官网、默认有效期天数
- [ ] 提交成功后明确告知**下一步会发生什么**:
  - 码已入池 → 「已进入池子,当前水位 N」
  - 应用待审 → 「已提交,审核通过后你的码会自动生效」(不能让用户以为码丢了)
- [ ] 服务端去重命中时,提示「这个码已经在池子里了」(spec 11.5),且**不扣配额**
- [ ] 应用列表的获取与缓存策略(这个列表会被反复用,不要每次开表单都全量拉)

## 验收

- 给已上架应用贡献 → 立刻在首页「最新可领」里出现。
- 贡献一个重复的码 → 被拒,文案清楚,配额未扣。
- 提交一个库里没有的应用 → 进入待审,前台可见状态。
- 表单校验: 空值、超长、明显的非码内容(如一个句子)都有提示。
- 键盘可完成全流程,`aria-live` 播报提交结果。

## 不做什么

- 不做管理员的审核界面(T09)。
- 不做码的**有效性预校验**(不联网验证邀请码是否可用,超出范围)。
