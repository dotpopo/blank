# T05 · 首页: 水位、最新可领、一键领取、骰子

| | |
|---|---|
| 依赖 | T03, T04 |
| 阻塞 | T07, T10 |
| 预估会话数 | 1 到 2 |

## 目标

首页是整个产品**唯一的转化动作**所在。它的成败只看一件事:
**一个陌生人打开页面,能不能在 5 秒内理解「这里可以拿一个码」,并真的拿到。**

参照工作区 `index.html` 的**信息结构**(品牌区、水位区、可领列表、贡献入口),
但**丢弃它的全部演示内容**: 演示应用、演示文案、「演示数据」标签、原型提示条一律不要。

## 交付物

- [ ] 品牌与页头(沿用「开门 OpenDoor」这个命名,除非用户另有指示)
- [ ] **水位区**: 池子总数(大字号,一眼可读)、今日新增、今日被领走
- [ ] **最新可领列表**: 默认 20 条
  - 每条显示: 应用图标、应用名、分类、**到期倒计时**、领取按钮
  - **不显示码文**(见 Q3)。码文只在领取后揭示
  - 剩余 < 24h 的条目有「快过期」的视觉强调(spec 11.2)
  - 排序按到期紧迫度,不按创建时间
- [ ] **一键领取**: 点击 → 调 `claim_code` → 成功则
  - 写入剪贴板
  - 弹出确认卡: 应用名 + 码文(可手动选中)+ 到期时间 + 「已复制」(spec 11.9)
  - 水位数字**立即减 1**(乐观更新,失败回滚)
  - 扣减本地配额
- [ ] **骰子**: 一个明确的入口,点击随机取一个码。行为与领取一致(揭示、复制、扣配额)
- [ ] **贡献入口**: 按钮跳 T06 的流程(本工单只需接好入口)
- [ ] 空池子状态: 池子为空时页面不能是一片空白,要引导「贡献第一个码」
- [ ] 剪贴板 API 失败时降级为「手动选中」(spec 11.10)

## 验收

- 领取成功后,池子总数**确实**减少 1(不是只改了 UI)。
- 领取同一码两次: 第二次明确提示「已经被领走了」。
- 空池子、加载中、请求失败三种状态都有像样的界面。
- 用键盘可以完成「领取」全流程。
- `prefers-reduced-motion` 下水位数字的变化不依赖动画传达。

## 不做什么

- 不做贡献表单本体(T06)。
- 不做配额耗尽态的完整逻辑(T07),但要**预留调用点**。
- 不做大盘(T08)。
