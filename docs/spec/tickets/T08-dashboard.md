# T08 · 大盘: 新增 vs 消费

|---|---|

## 目标

让**供需是否失衡**一眼可见。这是 spec 第 4 节说的「水位计」的另一半。

大盘是**给池子看的,不是给用户看的**,所以它不追求信息量,追求**一眼可读**。

## 核心指标(按重要性)

1. **净水位**: 当前池子总数,以及相对 7 天前的变化
2. **中位领取时长**: 码从入池到被领走的中位耗时(spec 11.3)。**这是最重要的一个数字**
3. **新增 vs 消费**: 两条线,7 天与 30 天可切
4. **过期未领数**: 今天有多少码白白过期(spec 11.2)
5. 应用维度的 Top N(哪些应用在被消耗,哪些在积压)

## 交付物

- [ ] `/dashboard` 路由
- [ ] 趋势图: 新增线 + 消费线 + 净水位。**两条线加一条,不要再堆**
- [ ] 时间范围切换(7 / 30 天)
- [ ] 中位领取时长用**文字 + 单位**呈现,不塞进图表
- [ ] 应用维度榜单: 消耗最快 / 积压最多
- [ ] **数据不足时如实说明**。池子只有 3 条数据时不要画一条看起来很有说服力的曲线
- [ ] 图表用真实数据。禁止为了「好看」而造点

## 验收

- 新增一条码,大盘的「今日新增」立刻反映。
- 领走一条,「今日消费」与净水位都反映。
- 池子数据极少时,页面显示「数据量不足,趋势暂不可用」而不是画一条直线。
- 窄屏下图表可读(不是横向滚动看半张图)。
- 图表有文字替代(屏幕阅读器能读到关键数字)。

## 不做什么

- 不做实时推送(轮询或按需刷新即可)。
- 不做导出、不做自定义报表。
- 不引入图表库之外的重型依赖(模板已有能力够用就够用)。
